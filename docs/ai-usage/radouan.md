# Usage de l'IA : Radouan

## Comment j'ai utilisé l'IA

Pour mes issues (#1, #2, #3, #5), je vais être honnête : le code a été écrit par l'IA (Claude Code, dans VS Code), pas tapé par moi. Mon travail a été de piloter : lui donner une issue à la fois, lui faire lire le `CLAUDE.md` de l'équipe pour qu'elle respecte nos règles, regarder ce qu'elle proposait et décider de ce qu'on garde.

Ce qui compte pour moi, c'est que je ne rends pas du code que je ne comprends pas. Pour chaque issue, j'ai demandé une doc qui explique les choix (`docs/client-api.md`, `docs/catalogue.md`, `docs/recherche.md`, `docs/filtre-prix.md`). Je suis capable d'expliquer chaque choix, de dire pourquoi l'autre solution a été rejetée, et de modifier le code si on me le demande. Quelques exemples de ce que je sais changer et où :

- passer à 24 produits par page : `CATALOG_PAGE_SIZE` dans `utils/catalogQuery.ts`, la pagination suit toute seule ;
- changer le délai de la recherche : `SEARCH_DEBOUNCE_MS` dans `utils/catalogSearch.ts` ;
- afficher un nouveau champ sur les cartes quand un filtre de prix est actif : l'ajouter dans `ProductSummary` (`types/dummyjson.ts`), et TypeScript oblige alors à l'ajouter aussi dans `PRODUCT_SUMMARY_FIELDS` ;
- changer les règles d'un prix saisi (par exemple refuser 0) : `parsePrice` dans `utils/catalogQuery.ts`, qui sert à la fois pour l'URL et pour le formulaire.

Ce que j'ai appris en faisant comme ça : l'IA va vite, mais elle ne voit pas tout seule les problèmes qui n'apparaissent que dans un vrai navigateur. Les meilleurs moments, c'est quand on a testé dans Chromium et trouvé des bugs que les tests unitaires ne voyaient pas (voir le tableau). Je retiens aussi qu'il faut vérifier les vraies réponses de l'API avant d'écrire du code, et ne pas croire la doc.
